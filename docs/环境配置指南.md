# Agent Studio 环境配置指南（小白向）

这份文档只讲一件事：**环境变量写在哪、怎么配、配完怎么检查**。

不需要把所有项一次配齐。按下面「最小可用 → Git 机器人 → Dify」三层往上加即可。

---

## 1. 先搞清三个服务

| 服务 | 干什么 | 默认端口 | 配置文件放哪里 |
|------|--------|----------|----------------|
| **Studio API** | 后端：登录、团队、工单、项目、克隆仓库、对接 Dify | `8790` | `apps/studio-api/.env` |
| **Studio Web** | 浏览器管理台（需登录 → 选团队） | `5173` | 一般不用 `.env`（开发时走 Vite 代理） |
| **Bridge** | 执行器：真正跑 Agent、改代码、commit/push、开 MR | `8787` | `apps/studio-bridge/.env` |
| **MySQL** | 账号 / 团队 / 项目 / 工单 / 运行日志（API 依赖） | **`3316`（Docker 推荐）** | `deploy/mysql/docker-compose.yml` |

关系可以记成：

```text
浏览器 → Studio Web（JWT）→ 选团队 → Studio API → MySQL（用户/团队/项目/工单/日志）
                              ↘ YAML（流水线/数字人/Bridge 登记/团队设置）
                              ↘ Bridge →（改仓 / git / MR）
                              ↘ Dify Workflow
```

**记住：**

- 登录账号、团队、项目、工单、运行日志 → **MySQL**（`STUDIO_MYSQL_*`）
- Git 提交作者、SSH 推送、开 Merge Request → 几乎都在 **Bridge** 的 `.env`
- 克隆仓库用 SSH → **Studio API** 的 `.env`（和 Bridge 用同一把 SSH 私钥）
- Cursor / Trae / Qoder 的 Key → **Bridge** 的 `.env`

## 1.1 MySQL + 登录（必做）

Studio API **必须能连上 MySQL**，否则无法启动鉴权与项目。**推荐 Docker**，不要依赖本机另装的 MySQL。

### 用 Docker 启动（推荐）

```bash
# 仓库根目录
docker compose -f deploy/mysql/docker-compose.yml up -d

# 建库 + 建表（可重复执行）
mysql -h 127.0.0.1 -P 3316 -u root -p123456 < apps/studio-api/sql/init.sql
```

- Compose：[`deploy/mysql/docker-compose.yml`](../deploy/mysql/docker-compose.yml)（别名 `apps/studio-api/docker-compose.mysql.yml`）
- SQL：[`apps/studio-api/sql/init.sql`](../apps/studio-api/sql/init.sql)  
  表：`users` / `teams` / `team_members` / `projects` / `work_orders` / `run_logs` / `run_log_entries`

默认 root 密码为 `123456`；若修改，请同步改 compose 与 `.env`。

Agent 自动搭建流程见 Skill：[`skills/local-stack-setup/`](../skills/local-stack-setup/)（含 [mysql.md](../skills/local-stack-setup/mysql.md)）。

### 写进 `apps/studio-api/.env`

```bash
STUDIO_MYSQL_HOST=127.0.0.1
STUDIO_MYSQL_PORT=3316
STUDIO_MYSQL_USER=root
STUDIO_MYSQL_PASSWORD=123456
STUDIO_MYSQL_DATABASE=agent_studio

STUDIO_JWT_SECRET=请改成随机长字符串
STUDIO_ADMIN_USER=admin
STUDIO_ADMIN_PASSWORD=admin123
```

首次启动（用户表为空）会自动创建管理员，并建立 slug=`default` 的「默认团队」。  
若 `data/projects`、`data/work-orders`、`data/run-logs` 仍有旧文件，会**一次性迁入** MySQL（源文件保留）。

浏览器打开 Web → `/login` → **选择团队** → 进入工作台。系统管理员可在「团队管理」创建用户并拉入成员（含只读 `viewer`）。

公开接口：`GET /api/health`、`POST /api/auth/login`（及空库时的 register）。其余 API 需 `Authorization: Bearer <token>`。Bridge 注册仍用 `STUDIO_BRIDGE_TOKEN`，不走用户 JWT。

## 2. 配置文件从哪里来

仓库里只有「示例」，不会自动生效。你要自己复制一份改名：

```bash
# 在仓库根目录执行

# Bridge（必做，否则 Agent / Git 不会按你的配置跑）
cp apps/studio-bridge/.env.example apps/studio-bridge/.env

# API（必做：MySQL / JWT / 管理员；再按需加 Dify、SSH）
cp apps/studio-api/.env.example apps/studio-api/.env
```

然后用编辑器打开对应的 `.env` 改内容。

| 文件 | 作用 |
|------|------|
| `apps/studio-bridge/.env` | **你日常主要改这个** |
| `apps/studio-api/.env` | **MySQL、JWT、管理员**、API 端口、Dify、克隆 SSH |
| `packages/bridge/.env.example` | 给发布包看的完整注释模板，本地调试一般不用它当运行配置 |
| `apps/*/ .env` | **不要提交到 Git**（含密钥） |

改完 `.env` 后要 **重启对应进程** 才会生效。

## 3. 最小可用（能打开页面、能跑 Agent）

### 3.1 编辑 `apps/studio-bridge/.env`

```bash
BRIDGE_PORT=8787
BRIDGE_HOST=0.0.0.0
BRIDGE_NAME=local-dev

# 用 Cursor 跑代码（最常见）
AGENT_DRIVER=cursor
CURSOR_API_KEY=你的_cursor_key
# CURSOR_MODEL=composer-2.5
```

`CURSOR_API_KEY` 去哪里拿：打开 [Cursor Dashboard → API](https://cursor.com/dashboard/api) 创建。

也可以不写 Key，改用浏览器登录：

```bash
cd apps/studio-bridge
node ../../packages/bridge/dist/bin.js start --login
```

### 3.2（可选）让 Bridge 登记到 Studio

两边写 **同一个** token：

`apps/studio-bridge/.env`：

```bash
STUDIO_URL=http://127.0.0.1:8790
STUDIO_BRIDGE_TOKEN=dev-bridge-token
BRIDGE_PUBLIC_URL=http://127.0.0.1:8787
```

`apps/studio-api/.env`：

```bash
STUDIO_BRIDGE_TOKEN=dev-bridge-token
```

### 3.3 启动

```bash
# 仓库根目录，三个终端
npm run build:schema   # 第一次或 schema 变更后
npm run build:runtime

npm run dev:api        # 或：cd apps/studio-api && node dist/main.js
npm run dev:web
npm run dev:bridge     # 会读 apps/studio-bridge/.env
```

检查：

- API：http://127.0.0.1:8790/api/health
- 管理台：http://127.0.0.1:5173
- Bridge：http://127.0.0.1:8787/health

Bridge 启动日志里应能看到类似：`agent driver: cursor`。

## 4. Git 机器人 + SSH（推荐，避免用个人身份推代码）

目标：

1. **commit 作者** 显示为 bot（不是你的本机 `git config user.name`）
2. **push** 走 SSH + bot 私钥
3. **开 MR** 走 HTTP API + bot 的 Personal Access Token（PAT）

本地 GitLab 常见端口（按你的 compose 为准）：

| 用途 | 常见地址 |
|------|----------|
| 网页 / HTTP clone | `http://localhost:8929` |
| API | `http://localhost:8929/api/v4` |
| SSH | 端口 **`2224`**（不是 22） |

> GitLab 本体（Docker、端口 8929/2224、建仓）见：[本地Dify与GitLab搭建指南.md §2](./本地Dify与GitLab搭建指南.md)。

### 4.1 生成 SSH 密钥（本机执行一次）

```bash
ssh-keygen -t ed25519 -f ~/.ssh/agent_studio_bot -N "" -C "agent-studio-bot@local"
cat ~/.ssh/agent_studio_bot.pub
```

把打印出来的 **公钥** 整行复制。

### 4.2 把公钥挂到 GitLab

1. 打开 GitLab → 头像 → **Preferences / 偏好设置** → **SSH Keys**
2. 粘贴公钥，Title 填 `agent-studio-bot`，保存

（生产环境建议单独建一个 bot 用户；本地调试挂在现有用户也可以。）

### 4.3 创建 PAT（用来开 Merge Request）

1. GitLab → **Access Tokens**（用户或 Project Token）
2. 勾选至少：`api`、`write_repository`（按你的 GitLab 版本勾选相近权限）
3. 复制 `glpat-...`（只显示一次）

### 4.4 写入 `apps/studio-bridge/.env`

```bash
# 提交显示的作者（强制覆盖本机 git 身份）
BRIDGE_GIT_AUTHOR_NAME=agent-studio-bot
BRIDGE_GIT_AUTHOR_EMAIL=bot@agent-studio.local
BRIDGE_GIT_FORCE_AUTHOR=true

# SSH 推送
BRIDGE_GIT_PREFER_SSH=true
BRIDGE_GIT_SSH_KEY=~/.ssh/agent_studio_bot
BRIDGE_GIT_SSH_PORT=2224
BRIDGE_GIT_SSH_USER=git

# review 通过后自动开 MR
BRIDGE_GIT_CREATE_PR=true
BRIDGE_GIT_PUSH=true
GITLAB_TOKEN=glpat-请换成你的token
BRIDGE_GITLAB_API=http://localhost:8929/api/v4
BRIDGE_GITLAB_WEB=http://localhost:8929
```

若用 **GitHub**，不配 GitLab 那几项，改配：

```bash
GITHUB_TOKEN=ghp_xxx
# 或 BRIDGE_GITHUB_TOKEN=ghp_xxx
```

### 4.5 写入 `apps/studio-api/.env`（克隆也走 SSH）

```bash
STUDIO_GIT_PREFER_SSH=true
STUDIO_GIT_SSH_KEY=~/.ssh/agent_studio_bot
STUDIO_GIT_SSH_PORT=2224
STUDIO_GIT_SSH_USER=git
```

说明：API 也认 `BRIDGE_GIT_SSH_*` 同名变量；两套写一样即可，避免只配了一边。

### 4.6 已有本地克隆：把 origin 改成 SSH

若仓库之前是 `http://localhost:8929/...`，可手动改成 SSH（组名/仓名换成你的）：

```bash
git -C <本地仓库路径> remote set-url origin \
  ssh://git@localhost:2224/<group>/<repo>.git
```

或等下次跑工单时由 Bridge 在 prefer-SSH 开启时自动改写。

### 4.7 自检 SSH

```bash
export GIT_SSH_COMMAND='ssh -i ~/.ssh/agent_studio_bot -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new'

git ls-remote ssh://git@localhost:2224/root/你的仓库.git HEAD
```

能打印出一串 commit hash 就说明通了。

重启 Bridge 后，日志应出现类似：

```text
git bot identity: agent-studio-bot <bot@agent-studio.local>; ssh_key=true; prefer_ssh=true
```

## 5. Dify（要用工作流编排时再配）

**先把本机 Dify / GitLab 容器跑起来**，步骤见：[本地Dify与GitLab搭建指南.md](./本地Dify与GitLab搭建指南.md)。

Studio 侧可以写在 `apps/studio-api/.env`，也可以在管理台 **设置** 页填写（UI 会落到 `data/dify-config.yaml`）。

```bash
DIFY_ENABLED=true
DIFY_API_BASE=http://localhost/v1
DIFY_API_KEY=app-xxxxxxxx

# Dify 容器里访问你本机 Bridge 时常用：
DIFY_BRIDGE_BASE_URL=http://host.docker.internal:8787

# 可选：Console 登录（导入 DSL 等）
# DIFY_CONSOLE_BASE=http://localhost/console/api
# DIFY_CONSOLE_EMAIL=admin@example.com
# DIFY_CONSOLE_TOKEN=
```

注意：`DIFY_BRIDGE_BASE_URL` 是 **Dify 所在环境** 访问 Bridge 的地址，不是浏览器访问地址。

## 6. 变量一览（按文件）

### 6.1 `apps/studio-bridge/.env`

| 变量 | 必填？ | 默认 / 示例 | 含义 |
|------|--------|-------------|------|
| `BRIDGE_PORT` | 建议 | `8787` | Bridge 监听端口 |
| `BRIDGE_HOST` | 否 | `0.0.0.0` | 监听地址 |
| `BRIDGE_NAME` | 否 | 主机名 | 在「执行器」页显示的名字 |
| `BRIDGE_PUBLIC_URL` | 登记时建议 | `http://127.0.0.1:8787` | 告诉 Studio：怎么回调到这台 Bridge |

| `CURSOR_API_KEY` | cursor 时 | — | Cursor API Key |
| `CURSOR_MODEL` | 否 | — | 如 `composer-2.5` |
| `TRAECLI_PERSONAL_ACCESS_TOKEN` | trae 时 | — | Trae Token |
| `QODER_PERSONAL_ACCESS_TOKEN` | qoder 时 | — | Qoder Token |
| `STUDIO_URL` | 登记时 | `http://127.0.0.1:8790` | Studio API 地址 |
| `STUDIO_BRIDGE_TOKEN` | 登记时 | 与 API 一致 | 注册共享密钥 |
| `BRIDGE_GIT_AUTHOR_NAME` | Git 推荐 | `agent-studio-bot` | 提交作者名 |

| `BRIDGE_GIT_SSH_KEY` | Git 推荐 | `~/.ssh/agent_studio_bot` | 私钥路径；文件存在也会自动 prefer SSH |
| `BRIDGE_GIT_SSH_PORT` | 本地 GitLab | `2224` | 非 22 端口会写进 `ssh://git@host:PORT/...` |
| `BRIDGE_GIT_SSH_USER` | 否 | `git` | SSH 用户名 |
| `BRIDGE_GIT_PUSH` | 否 | — | 是否允许推送（按你现有配置） |
| `BRIDGE_GIT_CREATE_PR` | 否 | `true` | review 后是否自动开 MR/PR |
| `GITLAB_TOKEN` | 开 GitLab MR | `glpat-...` | 建议 bot 用户的 PAT |
| `BRIDGE_GITLAB_API` | GitLab | `http://localhost:8929/api/v4` | API 根路径 |
| `BRIDGE_GITLAB_WEB` | GitLab | `http://localhost:8929` | 网页根路径（拼 MR 链接） |
| `GITHUB_TOKEN` | 开 GitHub PR | `ghp-...` | GitHub 用 |
| `BRIDGE_WORKSPACE_ROOTS` | 少用 | `examples/` | 未绑项目时扫描 `AGENTS.md` 的根 |
| `BRIDGE_AGENTS_PATHS` | 少用 | — | 直接指定若干 `AGENTS.md` 路径 |

## 8. 常见问题

**Q：改了 `.env` 没效果？**  
A：重启对应服务。Bridge 看 `8787`，API 看 `8790`。

**Q：commit 还是我的名字？**  
A：确认 Bridge 日志里有 `git bot identity: agent-studio-bot ...`，且 `BRIDGE_GIT_FORCE_AUTHOR` 不是 `false`。Agent 提示里也会要求不要覆盖环境里的作者。

**Q：`Permission denied (publickey)`？**  
A：检查公钥是否挂到 GitLab、`BRIDGE_GIT_SSH_KEY` 路径对不对、SSH 端口是否真是 `2224`、`origin` 是否已是 `ssh://git@localhost:2224/...`。

**Q：能 push 但不开 MR？**  
A：看 `GITLAB_TOKEN` 是否有效、是否有 `api` 权限；`BRIDGE_GITLAB_API` / `WEB` 是否指向你的 GitLab；`BRIDGE_GIT_CREATE_PR` 是否为 `false`。

**Q：密钥能不能提交到仓库？**  
A：**不能。** 只提交 `.env.example`，真正的 `.env` 留在本机。
