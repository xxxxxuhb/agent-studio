# 团队级密钥：轮换与最小权限

Agent Studio 把 **Dify / Console /（可选）Studio Git SSH** 按团队隔离到：

`apps/studio-api/data/team-secrets/{teamId}.yaml`（文件模式 `0600`）

空字段回退到安装级：`DIFY_*` 环境变量 → `data/dify-secrets.yaml` → `data/dify-config.yaml`。

Bridge 执行机上的 `BRIDGE_GIT_*` / `GITLAB_TOKEN` **不属于团队文件**，仍是每台执行机自己的 `.env`。

## 解析优先级

| 用途 | 顺序 |
|------|------|
| Workflow App API Key | 流水线 Dify 绑定 → **团队** `api_key` → 安装级 |
| Console Token（DSL 导入/发布） | **团队** → 安装级 |
| `bridge_base_url` / `agents_md_path` | **团队** → 安装级 |
| Studio `ensureCloned` SSH | **团队** `git_ssh_*` → `STUDIO_GIT_*` / `BRIDGE_GIT_*` |
| Bridge 拉仓 / 推 MR | 仅执行机 `BRIDGE_GIT_*` + bot PAT |

API：`GET/PUT /dify/config?team_id=`（成员可读，owner/member 可写；viewer 只读由团队门禁保证）。

## 最小权限建议

1. **Dify App Key**：每个团队用独立 Workflow App（或独立 Key）；不要把安装级 Key 发给所有租户当唯一密钥。
2. **Console 账号**：仅用于 DSL 导入的运维账号；不要用个人超管日常密码；登录后 Token 只写在该团队 secrets 文件。
3. **Git**：执行机 bot 用户 + Deploy Key / Maintainer PAT，按仓库最小权限；团队级 `git_ssh_key_path` 仅给需要本机调试克隆的场景。
4. **文件权限**：`team-secrets/` 与 `dify-secrets.yaml` 保持 `0600`；备份加密；勿提交进 git。
5. **成员角色**：viewer 不能改设置；轮换密钥后通知 owner 在「设置」里重登 Console / 更新 App Key。

## 轮换步骤

### Dify App API Key

1. 在 Dify 为该团队 App 重新生成 API Key。
2. Studio → 选中团队 → 设置 → 粘贴新 Key → 保存。
3. 「测试连通」确认 `auth_source=team`（或流水线绑定仍优先）。
4. 作废旧 Key。

### Console Token

1. 设置 → 输入 Console 邮箱/密码 →「登录并获取 Token」（写入当前团队）。
2. 或手动粘贴新 access_token。
3. 对需要的流水线再执行一次「一键导入到 Dify」验证。

### Git SSH（Studio 本机）

1. 轮换 bot 私钥后更新团队设置中的 `git_ssh_key_path`（或安装级 `STUDIO_GIT_SSH_KEY`）。
2. Bridge 主机同步更新 `.env` 的 `BRIDGE_GIT_SSH_KEY` 并重启 Bridge。

### 安装级默认

仅当所有团队共用同一 Dify 实例时保留 `DIFY_API_KEY` / `dify-secrets.yaml`；多租户生产环境应清空安装级 Key，强制每团队填写。
