# 团队级密钥：轮换与最小权限

Agent Studio（`v2`）把 **Bridge / Git SSH / 语言** 等按团队隔离到：

`apps/studio-api/data/team-secrets/{teamId}.yaml`（文件模式 `0600`）

空字段回退到安装级：`data/studio-config.yaml` → 环境变量（`STUDIO_BRIDGE_BASE_URL` / `STUDIO_GIT_*` 等）。

旧文件里若仍有 Dify 相关键名，解析时会忽略（`TeamSecretsSchema` passthrough + 选择性读取）。

Bridge 执行机上的 `BRIDGE_GIT_*` / `GITLAB_TOKEN` / Agent Key **不属于团队文件**，仍是每台执行机自己的 `.env`。

## 解析优先级

| 用途 | 顺序 |
|------|------|
| `bridge_base_url` | **团队** secrets / 团队设置 → 安装级 `studio-config` → `STUDIO_BRIDGE_BASE_URL` |
| `agents_md_path` | **团队** → 安装级 → `STUDIO_AGENTS_MD_PATH` |
| Studio `ensureCloned` SSH | **团队** `git_ssh_*` → `STUDIO_GIT_*` / `BRIDGE_GIT_*` |
| Bridge 拉仓 / 推 MR / 跑 Agent | 仅执行机 `BRIDGE_GIT_*` + bot PAT + Agent Key |
| Bridge HTTP / WS 注册 | 安装级 `STUDIO_BRIDGE_TOKEN`（与 `BRIDGE_HTTP_TOKEN` 对齐） |

设置页：选中团队后读写当前团队的 `bridge_base_url` / Git SSH / 语言（不再有 `/dify/config`）。

## 最小权限建议

1. **Bridge token**：安装级共享密钥即可；生产环境用强随机串，勿提交进 git。
2. **Git**：执行机 bot 用户 + Deploy Key / Maintainer PAT，按仓库最小权限；团队级 `git_ssh_key_path` 仅给需要本机调试克隆的场景。
3. **文件权限**：`team-secrets/` 与 `studio-config.yaml` 中含路径的配置保持本机私密；备份加密；勿提交进 git。
4. **成员角色**：viewer 不能改设置；轮换密钥后通知 owner 在「设置」里更新 Bridge URL / SSH 路径。

## 轮换步骤

### Bridge 注册 / HTTP token

1. 生成新 `STUDIO_BRIDGE_TOKEN`，写入 Studio API 与各 Bridge `.env`（`STUDIO_BRIDGE_TOKEN` / `BRIDGE_HTTP_TOKEN`）。
2. 重启 API 与 Bridge；确认执行器页 `online`，`GET /health` 正常。
3. 作废旧 token。

### Bridge base URL（团队）

1. Studio → 选中团队 → 设置 → 更新 `bridge_base_url`（远程执行机用可达 URL，勿写笔记本 `127.0.0.1`）。
2. 或改执行机 `BRIDGE_PUBLIC_URL`，让 WS 登记覆盖默认。

### Git SSH（Studio 本机）

1. 轮换 bot 私钥后更新团队设置中的 `git_ssh_key_path`（或安装级 `STUDIO_GIT_SSH_KEY`）。
2. Bridge 主机同步更新 `.env` 的 `BRIDGE_GIT_SSH_KEY` 并重启 Bridge。

### GitLab / GitHub PAT（开 MR）

1. 在 Forge 为 bot 重新签发 PAT（`api` + `write_repository`）。
2. 只更新 **Bridge** `.env` 的 `GITLAB_TOKEN` / `GITHUB_TOKEN` 并重启。
3. 作废旧 PAT。
