# Agent Studio — 架构与时序图

控制面（Studio）与执行面（Bridge）分离；Dify 负责任务编排与人工闸门；GitLab 托管代码与 MR。

相关文档：[环境配置指南](./环境配置指南.md) · [本地 GitLab](./本地GitLab搭建指南.md) · Skill [`skills/local-stack-setup`](../skills/local-stack-setup/)

|------|------|----------|

| orchestrator | 按流水线步骤调 Bridge stages + 人工闸门 | `packages/orchestrator` |
| agent-runtime | 可插拔 Agent 驱动 | `packages/agent-runtime` |

## 3. 工单主路径时序（Studio 编排器）

```mermaid
sequenceDiagram
  autonumber
  actor U as 用户
  participant Web as Studio Web
  participant API as Studio API
  participant Orch as orchestrator
  participant Bridge as Bridge
  participant Git as Git 工作副本
  participant GL as GitLab

  U->>Web: 开始流水线
  Web->>API: POST /work-orders/:id/start
  API->>Bridge: POST /workspace/ensure
  Bridge-->>API: local_path / agents_md_path
  API->>Bridge: POST /routing/select
  Bridge-->>API: repo_ids / agents_md_path
  API->>Orch: startStudioRun (后台)
  Orch->>Bridge: POST /runs
  Bridge-->>Orch: run_id

  loop 各阶段 (requirement / plan / dev / review …)
    Orch->>Bridge: POST /runs/:id/:stage
    Bridge->>Git: Agent 改文件 / 写产物
    Bridge-->>Orch: stage result
    opt human_approval
      API-->>Web: pending_approval
      U->>Web: 通过 / 驳回
      Web->>API: POST .../decision
      API->>Orch: applyStudioDecision
      Orch->>Bridge: POST /runs/:id/decision
    end
  end

  Note over Bridge,Git: review 通过后
  Bridge->>Git: commit (bot author) + SSH push
  Bridge->>GL: 创建 MR (GITLAB_TOKEN)
  API-->>Web: 状态 / MR 链接
```

要点：

1. **工作区**由 Bridge `POST /workspace/ensure` 准备（`BRIDGE_REPOS_DIR`），再 **选仓** `POST /routing/select`；`routing_mode=explicit`。  
2. Studio → Bridge 调用带 `Authorization: Bearer`（`STUDIO_BRIDGE_TOKEN`）。  
3. Human Input 在 Studio 审批，经 orchestrator 调 Bridge `/decision`。  
4. Push 用 **SSH bot key**；开 MR 用 **bot PAT**（与 push 凭证分离）。  
5. 产物目录名可能仍为 `docs/dify-runs/{run_id}/`（历史路径）。

## 4. 流水线自然语言生成（compose）

```mermaid
sequenceDiagram
  participant Web as Studio Web
  participant API as Studio API
  participant Bridge as Bridge
  participant Agent as Agent driver

  Web->>API: POST /pipelines/compose
  API->>Bridge: POST /compose/pipeline
  Bridge->>Agent: 生成 JSON 草稿
  Agent-->>Bridge: draft
  Bridge-->>API: draft
  alt 校验失败 / Bridge 不可用
    API->>API: rules 回退 composePipelineFromPrompt
  end
  API-->>Web: Pipeline draft（可保存到 MySQL）
```

导入 Dify：`pipelines/:id/dify-import` → Console DSL 导入并 **publish**（需 Console Token）。

## 5. 鉴权关系

```mermaid
flowchart TB
  Token["STUDIO_BRIDGE_TOKEN\n(= BRIDGE_HTTP_TOKEN)"]
  Token --> WS["Bridge → API\nSocket.IO /bridges 注册"]
  Token --> SH["Studio → Bridge\nAuthorization: Bearer"]
  Token --> DT["Dify inputs.bridge_token\n→ HTTP Authorization"]

  SSH["BRIDGE_GIT_SSH_KEY\n+ prefer SSH :2224"] --> Push["git push"]
  PAT["GITLAB_TOKEN\nbot PAT"] --> MR["GitLab Merge Request API"]
  AppKey["Dify App Key"] --> WF["Studio → Dify /v1"]
```

| 密钥 | 用途 |
|------|------|
| `STUDIO_BRIDGE_TOKEN` | Bridge HTTP + WS 注册；Studio/Dify 调 Bridge |
| `GITLAB_TOKEN` | 开 MR |
| `BRIDGE_GIT_SSH_*` | clone/push SSH |
| `DIFY_API_KEY` / `dify-secrets.yaml` | 启动/同步 Workflow |
| `CURSOR_API_KEY` 等 | Bridge 侧 Agent 驱动 |
